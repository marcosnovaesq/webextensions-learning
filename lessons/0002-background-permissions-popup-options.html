Background Scripts, Permissions, Popup & Options — Wired Together

Four pieces from Lesson 1's map, but this time you'll wire them into one working loop: options page → storage → background script → popup. That loop — a setting the user changes somewhere, remembered somewhere, and used somewhere else — is one of the most common shapes in real extensions, shuff included.

Four facts worth knowing before you build

Background scripts (Manifest V3) are always non-persistent. They unload after a few seconds idle and reload only when an event fires. Two rules follow: register listeners top-level and synchronously (never inside a callback, or the listener won't survive a reload), and never store state in a plain JS variable — use storage instead, because a global gets wiped every time the script unloads.[1]

Permissions are an array of strings that unlock APIs. Without "storage" in permissions, calling browser.storage.* fails outright. Manifest V3 splits URL-based access into its own host_permissions key — permissions is now just API names ("storage", "tabs", …) and special cases like "activeTab".[2]

A popup can only be opened by the user clicking the toolbar button — there's no API to open one from code, and it unloads the instant it loses focus. That's why a popup that needs to "remember" anything has to ask somewhere else (the background script, via storage) every time it opens.[3]

An options page is just another extension page — declared via options_ui.page, opened by the user through the browser's add-ons manager, or programmatically via browser.runtime.openOptionsPage(). It typically reads and writes settings through storage.sync, the same API the background script and popup use.[4]

TODO 0 — manifest.json

The starter manifest only declares the popup. Add three keys: permissions (so storage works), background (MV3 shape — a module-type script), and options_ui (pointing at options/options.html).

Reveal 
"permissions": ["storage"],
"background": {
  "scripts": ["background.js"],
  "type": "module"
},
"options_ui": {
  "page": "options/options.html",
  "open_in_tab": true
}

TODO 1 — background.js

Listen for a { type: "get-greeting" } message; respond with the saved greeting from storage.sync (default "Hello!").

Reveal 
browser.runtime.onMessage.addListener((message) => {
  if (message.type === "get-greeting") {
    return browser.storage.sync
      .get({ greeting: "Hello!" })
      .then((items) => items.greeting);
  }
});

TODO 2 & 3 — popup/popup.js

On load, ask the background script for the greeting and display it. On button click, open the options page.

Reveal 
document.addEventListener("DOMContentLoaded", async () => {
  const greeting = await browser.runtime.sendMessage({ type: "get-greeting" });
  document.getElementById("greeting").textContent = greeting;
});

document.getElementById("open-options").addEventListener("click", () => {
  browser.runtime.openOptionsPage();
});

TODO 4 & 5 — options/options.js

On load, fill the input from storage. On submit, save the input's value.

Reveal 
document.addEventListener("DOMContentLoaded", async () => {
  const { greeting } = await browser.storage.sync.get({ greeting: "Hello!" });
  input.value = greeting;
});

form.addEventListener("submit", async (event) => {
  event.preventDefault();
  await browser.storage.sync.set({ greeting: input.value });
});

Run it

  1. Open Firefox, go to about:debugging#/runtime/this-firefox.
  2. Click Load Temporary Add-on… and select experiments/0002-settings-roundtrip/manifest.json.
  3. Click the extension's toolbar icon. It should show Hello!.
  4. Click Change greeting, type something new, hit Save.
  5. Reopen the popup — it should show your new greeting. That round trip (options → storage → background → popup) is the whole lesson.

If it doesn't work: about:debugging has an Inspect link for the background script and the popup — use it, check the console for errors, and compare against the reveals above line by line.

Back to shuff

shuff's manifest still has no background, no permissions, no options_ui — this loop is the smallest real version of what adding any of them looks like. When shuff needs a setting (a duration, a list of blocked sites, anything), this is the shape: options page writes it, background script (or a content script, via messaging) reads it, popup reflects it.
