WebExtension Anatomy — Glossary

The components an extension can be built from, and the manifest.json key that wires each one in. Compressed from Lesson 1 for quick lookup later.

ComponentWhat it ismanifest.json key
manifest.json The one required file. Holds name, version, permissions, and pointers to every other component below. — (it is the manifest)
Background script Runs independently of any web page. Listens for browser-level events (new tab, clicked icon, installed). Non-persistent (unloads when idle) by default in Manifest V3; persistent pages were Manifest V2-only. background
Content script Runs inside a live web page's DOM — separate world from the page's own scripts. Can read/modify the DOM, inject CSS, and message the background script for full API access. content_scripts
Popup Small HTML page shown when the user clicks the toolbar/address-bar button. Closes when focus leaves it. Has full extension-API access. action.default_popup
Sidebar HTML page pinned in the browser's left pane, alongside the page content. Stays open across navigation. sidebar_action
Options page HTML page shown inside the browser's native add-ons/extensions manager when the user opens this extension's settings. options_ui
Extension page Any other HTML page with full API access, not tied to a predefined UI slot. Opened manually via tabs.create() / windows.create(). none required
Web accessible resource A packaged file (image, CSS, JS, HTML) exposed so content scripts / page scripts can load it by URL — e.g. an icon a content script inserts into the page. web_accessible_resources
Icons Images representing the extension itself and any toolbar buttons it defines. icons
Permissions Declared capabilities (host access, APIs) the extension is requesting. Gates which WebExtensions APIs are usable from background/content scripts. permissions

The two worlds

Privileged (extension) context — background scripts, popups, sidebars, options pages, extension pages. Full access to WebExtensions APIs (tabs, storage, etc.) as declared in permissions.

Page context — content scripts. Live inside a real web page's DOM, but in an isolated JS world from the page's own scripts. Can use only a small subset of WebExtensions APIs directly, and must message the background script for the rest.
